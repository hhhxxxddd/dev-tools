# dev-tools v0.5.5

## 中文

- 扫描范围按工作流、工作区与项目 `[scan]` 配置确定，不读取 `.gitignore`。默认跳过 `.local` 等运行数据目录；兜底递归达到深度上限时报告截断，支持显式纳入必要目录。
- 根级 mise 保持版本权威，检查包要求、Java/Rust 最低版本和子目录声明；单次检查复用元数据读取与解析。修复平台 Python 根目录漏扫、Cargo.lock 分类及 Rust 通道空白处理，辅助元数据读取拒绝特殊文件，JSON 健康探测限制持续慢响应。
- Rust/Cargo 与 Tauri 目录识别提取为静态框架规则。Rust/Tauri 的准备和启动仍由项目显式配置，工具不执行 npm 脚本猜测依赖或管理应用数据。
- 增加可选服务与 HTTP JSON 就绪检查，统一启动结果、回滚和维护恢复。客户端关闭或可选启动失败后保留共享服务；必需依赖必须实际就绪，仅含可选服务的项目保持一致状态展示。
- Windows worker 通过独立 Job Object 回收后代，控制台保持隐藏，图形子进程显式请求正常显示；不改变已运行窗口。WSL 保留原生进程组与 systemd 管理。
- 中英文 README 增加默认支持的项目类型，明确自动发现和手写工作流的范围。

已有项目无需重新注册。手写工作流将只扫描声明的相关目录；依赖之前的全目录扫描时，请补充工作区声明或 `[scan].roots`。业务数据、会话、令牌与发布版 sidecar 仍由应用管理。

详见[项目配置](../project-config.md)、[桌面示例](../../examples/dev-desktop.toml)与[开发说明](../development.md)。

## English

- Scanning follows workflow directories, workspace declarations and project `[scan]` settings without reading `.gitignore`. Runtime data such as `.local` is skipped by default; bounded fallback discovery reports truncation and explicit scopes can include necessary directories.
- Root mise declarations remain authoritative. Package requirements, Java/Rust minimum versions and nested declarations are checked conservatively, with per-operation metadata caching. Fixes platform Python scope omissions, Cargo.lock classification and Rust channel whitespace; auxiliary metadata reads reject special files and JSON readiness checks bound trickling response bodies.
- Rust/Cargo and Tauri scope conventions use static framework rules. Rust/Tauri preparation and startup remain explicit project workflows; the tool does not execute npm scripts to infer dependencies or manage application data.
- Optional services and HTTP JSON readiness share startup outcomes, rollback and maintenance recovery policy. Closing or failing an optional client preserves shared services; required dependencies must actually become ready, and optional-only projects have consistent status displays.
- Separate Windows Job Objects reclaim worker descendants. Console windows remain hidden while GUI children explicitly request normal display; existing windows are untouched. WSL retains native process groups and systemd.
- Both READMEs describe default project support and distinguish automatic discovery from explicit workflows.

Existing projects need no registration again. Manual workflows now scan their declared scopes; add workspace declarations or `[scan].roots` if they depended on broad recursive discovery. Applications retain ownership of business data, sessions, tokens and release sidecars.

See [project configuration](../project-config.en.md), the [desktop example](../../examples/dev-desktop.toml) and [development notes](../development.en.md).
