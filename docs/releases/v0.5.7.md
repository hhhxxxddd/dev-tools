# dev-tools v0.5.7

## 中文

- `list` 在表格后按项目、环境和状态显示“原因摘要”；`status` 展开具体诊断、恢复阶段、尝试次数、最近进展及日志命令。长摘要按终端显示宽度换行，正常项目不显示空区块。
- `start/prepare/restart/build` 失败和 JSON 使用相同的 `summary`、`diagnostics`。诊断保留 HTTP 状态、探测目标、连接异常、JSON 不匹配字段路径及 Compose 容器状态，以稳定代码供自动化判断。
- 异常日志线索最多提取两条脱敏首句，读取或分析最多 8 KiB；失败尝试与时间未确认的日志尾部分开标记，并限制到对应启动范围。敏感字段和 URL 凭据被隐藏，日志线索不作为已确认根因。
- 恢复期间保留最近失败并显示重试进度，成功或主动停止后不再显示旧错误。旧目标控制器使用有次数及耗时预算的只读补充查询，不触发部署、升级、提权或业务服务重启。
- 补齐中英文摘要、恢复阶段和跨端渲染验证，更新双语运行、项目配置、CLI 与开发文档。

已有项目无需重新注册。Windows 与 WSL 控制器分别更新；新日志范围与恢复元数据由后续正常启动的 worker 产生，查询不会重启现有 worker。旧端缺少详情时会明确提示，无法恢复历史未记录的失败原因。

详见[运行说明](../usage.md)、[CLI 约定](../cli-contract.md)和[项目声明](../project-config.md)。

## English

- `list` displays labeled reason summaries below its table, grouped by project, environment and state. `status` expands diagnostics, recovery stage, attempt count, last progress and log commands. Long summaries wrap to terminal display width; healthy projects produce no empty section.
- Failed `start/prepare/restart/build` operations and JSON share `summary` and `diagnostics`. Facts retain HTTP status, probe targets, connection exceptions, JSON mismatch paths and Compose container states, with stable codes for automation.
- Extracts at most two redacted exception first sentences from at most 8 KiB of log reads or analysis. Failed-attempt clues are separated from log tails with unverified event time and bounded to their startup attempt. Sensitive fields and URL credentials are hidden; clues do not assert a root cause.
- Retains the latest failure during recovery and displays retry progress, clearing stale errors after success or an explicit stop. Older target controllers receive bounded read-only supplementary queries without deployment, upgrades, elevation or business service restarts.
- Completes Chinese/English summary and recovery-stage coverage, cross-platform rendering checks and bilingual operation, project configuration, CLI and development documentation.

Existing projects need no registration again. Update Windows and WSL controllers separately. New log ranges and recovery metadata appear when workers next start normally; queries never restart existing workers. Missing details from older targets are explicit, and failures not recorded historically cannot be reconstructed.

See [operation](../usage.en.md), the [CLI contract](../cli-contract.en.md) and [project declarations](../project-config.en.md).
