# v0.5.4

## 中文

- 空闲同步从 0.75 秒逐步退避，等待最多 3 秒；原生文件监控从 0.5 秒退避到最多 1.5 秒。WSL 同步与监控复用 Git/依赖检查，仅目录元数据变化不再维持快速轮询。
- 定期完整检查仍覆盖依赖新增、升级、删除和未提交文件；变化后恢复快速检查，继续自动准备和热部署。构建前重新核实 Git/依赖状态，缓存过期、维护后及进程交接均有回退或快照保护。
- Windows 查询 WSL 的 `list/status` 自动检查 localhost：IPv4/IPv6 独立探测，常见 Web 服务等待 HTTP HEAD 响应，识别“端口可连接、网页不响应”；保留 WSL 本机健康事实，明确访问失败与旧端未检查。
- 查询 `package.json` 时跳过符号链接、FIFO 等特殊文件，仅解析不超过 1 MiB 的元数据；root 托管工作区不可读时回退源码元数据，不提权。跨端 status 校验目标环境和退出码。
- 补充双端隔离测试及 Windows 盘源码到 Linux ext4 工作区的真实验证，覆盖空闲唤醒、依赖增删升级、锁文件回写、热构建和停止后补齐。

```text
dev-tools list -e wsl
dev-tools status my-app -e wsl
dev-tools upgrade
dev-tools self update -e wsl
```

已有项目无需重新注册。Windows 和 WSL 各自更新；运行中更新的确认与恢复机制不变。空闲后的首次改动可能多等几秒，扫描、同步和构建本身的耗时另计。HTTP 可达不等同于完整页面或业务功能正常。

同步与热部署细节见[项目配置](../project-config.md)，访问检查和状态字段见[使用说明](../usage.md)与[接口约定](../cli-contract.md)。

## English

- Idle synchronization backs off from 0.75 seconds to at most 3 seconds of waiting; native file monitoring backs off from 0.5 seconds to at most 1.5 seconds. WSL workers share Git/dependency observations, and directory metadata alone no longer keeps fast polling active.
- Periodic full checks still cover dependency additions, upgrades, removals and uncommitted files. Changes restore fast checks and automatic preparation/hot deployment. Actions revalidate Git/dependency state; expired observations, maintenance and monitor handovers retain fallback or snapshot protection.
- Windows `list/status` queries for WSL check localhost access with separate IPv4/IPv6 probes. Recognized web services wait for an HTTP HEAD response, detecting accepting-but-silent relays while preserving WSL-local health facts and reporting failed or unchecked access explicitly.
- Package metadata reads skip symlinks, FIFOs and other special files and do not parse metadata larger than 1 MiB. Inaccessible root-owned workspaces fall back to source metadata without elevation. Cross-environment status validates the target environment and exit code.
- Adds isolated native tests and real Windows-mounted source to Linux ext4 workspace coverage for idle wakeup, dependency changes, lockfile writeback, hot builds and stop/catch-up behavior.

Existing projects need no registration again. Update Windows and WSL separately; running-update confirmation and restoration remain unchanged. The first edit after idling may take a few extra seconds, in addition to scanning, synchronization and build time. HTTP reachability does not prove complete page or business functionality.
