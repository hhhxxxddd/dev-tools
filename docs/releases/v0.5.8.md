# dev-tools v0.5.8

## 中文

- 为声明了构建策略的服务记录成功构建时的源码指纹；项目停止期间的源码、资源、文件结构和分支变化会被识别，`check` 展示待更新构建，启动或准备时先执行必要的结构构建。
- 构建失败或构建期间源码变化不会更新基线；控制器维护后的恢复也会在启动前重新核对。旧状态没有基线时保守构建一次。
- 补齐 Windows 与 WSL 的只读检查、构建和恢复回归测试，以及隔离项目的真实生命周期验证。

检查范围限于项目声明的 `watch` 路径中符合 `extensions` 或 `structural` 规则的文件，不能验证未声明的构建产物。已有项目无需重新注册；首次升级后，存在构建策略的项目下次准备或启动可能需要额外构建时间。

详见[项目声明](../project-config.md)和[运行说明](../usage.md)。

## English

- Records source fingerprints for successful builds of services with declared build policies. Changes to watched source, resources, file structure or branches while a project is stopped are detected; `check` reports builds requiring updates and start or prepare runs the necessary structural tasks first.
- Failed builds or source changes during a build do not update the baseline. Controller maintenance also rechecks freshness before restoring services. Existing state without a baseline triggers one conservative build.
- Adds Windows and WSL regression tests for read-only checks, builds and recovery, plus real lifecycle verification with isolated projects.

Checks cover files under declared `watch` paths matching `extensions` or `structural` rules; they do not validate undeclared build outputs. Existing projects need no registration again. Projects with build policies may need additional build time on their first preparation or start after updating.

See [project declarations](../project-config.en.md) and [operation](../usage.en.md).
