# v0.5.2

## 中文

- 帮助显示部署缺失和版本差异；指定环境的版本和帮助查询实际目标端。
- 跨端错误区分目标不可用、版本不兼容、命令不支持和响应无效，保留目标日志与有效 JSON 错误。
- 更新活动控制器时输入 `Y`，或使用 `--yes`，停止并恢复原先运行的服务与监控；WSL 更新失败回退控制器文件，失败恢复保留记录，可用 `self recover` 重试。
- `list` 默认汇总 Windows 与 WSL，增加声明端口和运行时类型列；显式 `-e` 只查询一端。
- `start --all` 启动当前或指定端的全部注册项目，跳过已有活动 worker 的项目，单项失败继续处理其他项目。
- 修复 Windows 列表 UTF-8 乱码；错误为红色、提示为黄色，状态列放到最后并按状态着色。重定向、`NO_COLOR` 和 JSON 输出不添加颜色。
- Windows 转发直接使用 WSL `--cd` 转换当前目录，减少一次调用，避免 `list` 重复打印代理网络提示。
- 汇总列表中不可用环境显示黄色提示；连接失败提示检查命令入口和跨端互通，避免误导为必须升级两端。
- `start` / `restart` 显示准备、依赖或构建任务、启动、健康检查及监控进度与耗时，长步骤每 5 秒更新提示。
- 健康检查等待及时响应 `stop`；跨端传输超时保留超时诊断，关闭进度输出管道不会中止项目启动，中文 Windows 宿主路径使用 UTF-8。
- 修复指定另一 Windows 源码升级后的恢复入口；WSL 失败回滚清理新增文件、恢复实际 systemd 单元，损坏的恢复记录在执行前拒绝。
- 启动中断回滚本次新增 worker 并保留恢复信息；修复 Windows 检出时 Bash 辅助入口的换行，增强双向传输测试的缓存隔离。

```powershell
dev-tools list
dev-tools start --all -e wsl
dev-tools self update -e wsl --yes
dev-tools upgrade --yes
```

## English

- Help reports missing deployments and version differences. Explicit target version and help queries use the actual target controller.
- Cross-platform errors distinguish unavailable targets, incompatible versions, unsupported commands and invalid responses, preserving target logs and valid JSON errors.
- Enter `Y`, or use `--yes`, to stop and restore previously active services and monitors during controller updates. Failed WSL deployment restores controller files; failed restoration retains a record for `self recover`.
- `list` defaults to Windows and WSL, with declared ports and runtime types. Explicit `-e` queries one side.
- `start --all` starts registered projects on the current or selected side, skips active projects, and continues after individual failures.
- Fixes UTF-8 corruption in Windows lists. Errors are red, notices yellow, and the last column shows colored states. Redirected output, `NO_COLOR` and JSON remain uncolored.
- Windows forwarding uses WSL `--cd` to translate the current directory, eliminating an extra invocation and duplicate proxy notices during `list`.
- Unavailable environments appear as yellow notices in summary lists. Connection failures direct users to check entrypoints and interop rather than unnecessarily update both installations.
- `start` / `restart` show preparation, dependency/build tasks, startup, health checks and monitor progress with elapsed time, updating every 5 seconds during long steps.
- Health-check waits respond promptly to `stop`; transport timeouts retain their diagnostics, closed progress pipes do not abort startup, and Unicode Windows host paths use UTF-8.
- Restores through the new entrypoint after upgrading from another Windows checkout. WSL rollback removes new files and restores actual systemd units; malformed recovery records are rejected before project operations.
- Interrupted startup rolls back newly started workers and retains recovery information. Fixes Bash helper line endings in Windows checkouts and isolates bidirectional transport test caches.
