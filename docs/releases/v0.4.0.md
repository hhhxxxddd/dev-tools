# dev-tools v0.4.0

这一版把项目依赖发现、环境准备和开发时的热部署整合到同一套 Windows / WSL 命令中，并提供 Scoop 安装与独立 WSL 部署。

## 依赖发现

- `scan` 读取现有工具版本和构建元数据，显示声明来源、版本冲突及缺失项。
- `init` 为 Node、Maven / Spring 和 Python 项目生成可检查的任务与服务配置，保留已有根配置；已有 Compose 项目使用容器声明。
- Maven 多模块项目可发现应用依赖的本地模块，用于编译监控和 Spring classpath 更新。
- `start` 自动准备环境；运行期间跟进依赖新增、升级、移除和模块变化，自动同步锁文件并恢复服务。`prepare --dry-run` 保留为计划预览。

## 热部署

- 前端使用项目开发服务器的热更新，FastAPI 服务使用 Uvicorn `--reload`。
- Spring 源码改动触发应用和依赖模块编译，再由 Spring DevTools 重载应用。
- 资源和结构变化执行对应构建，停止受影响服务及依赖方，并在完成后恢复。
- 分支 / HEAD 变化稳定后自动重新执行准备任务和结构构建，使用项目根明确声明的运行时，缺少已声明版本时自动准备。
- Windows 直接运行源码；WSL 持续同步源码到 Linux 工作目录，依赖和缓存各自保存。

热部署需要匹配项目声明；部分构建会短暂停服。无法确定的版本、自定义入口和复杂配置需要手动核对，运行时安装仅使用项目根 mise 中的明确版本；stop 停止自动维护，下次 start 补齐变化。

## 安装与使用

Release 和 bucket 清单发布后，在已有 Scoop 的 Windows 中执行：

```powershell
scoop bucket add dev-tools https://github.com/hhhxxxddd/dev-tools
scoop install dev-tools/dev-tools
dev-tools self update -e wsl
dev-tools help
```

仅需 Windows 时跳过 WSL 部署。WSL 发行版需要预先安装并启用 systemd，默认使用 Ubuntu。Scoop 安装后不需要进入 WSL 再克隆仓库；总览帮助会提示缺少的 WSL 部署。

在目标项目目录中，依次扫描、检查配置、准备并启动：

```text
dev-tools scan
dev-tools init --dry-run
dev-tools init
dev-tools register
dev-tools start
dev-tools status
```

原生 WSL 中的修改操作需要 `sudo`。`list` 默认显示名称、环境、状态表格；默认中文，可通过本机配置切换英文，JSON 字段保持稳定。

## 附件与更新注意事项

CLI 已精简：删除 `sync`、`self install` 和 `build --kind`，不保留旧入口。首次部署和更新统一使用 `self update`；手动构建使用 `build`，可通过 `--service` 选择服务。

| 附件 | 用途 |
|---|---|
| `dev-tools-0.4.0.zip` | Windows / WSL 控制程序、安装脚本、文档和示例；含逐文件校验清单 |
| `SHA256SUMS` | ZIP 的 SHA256 校验值 |
| `dev-tools.json` | 使用该 ZIP 校验值的 Scoop 清单 |

控制程序宿主使用 Python 3.14.8，由安装器准备，不使用项目的 Python。项目 TOML schema 为 1，项目命令 JSON schema 为 3；旧版命令和配置需要按文档核对。

Windows 与 WSL 分别更新。更新前停止对应平台的活动项目，更新后按需启动；安装器保留偏好、注册、状态、缓存和项目运行时。首次正式 Release 发布之前，请使用源码安装。

## English brief

- Removed sync, self install and build --kind without aliases. Use self update for first deployment and updates, and build with optional --service for manual builds.

- Discover tool versions, package workflows and local Maven module dependencies from existing project files.
- Start with automatic preparation. Follow dependency additions, upgrades, removals and module changes while running, synchronize lockfiles, and restore services; keep prepare for manual previews.
- Use framework development reloads, Spring compilation and DevTools reloads, and configured rebuilds after file or branch changes; some operations briefly stop services.
- Install Windows with Scoop and deploy the same controller version to WSL once. Keep platform runtimes and caches separate, and update each deployment explicitly.
