# dev-tools v0.5.1

## 中文

- 修复 WSL 项目因源码监控初始化超时而回滚服务、持续显示“待恢复”的问题。监控读取同步后的 Linux 工作目录，源码同步进程接收原目录改动；项目声明和 Git 状态仍从原源码读取。
- 优化文件快照扫描，减少重复文件属性查询，保留忽略目录、符号链接及非普通文件检查。维护或构建完成后更新快照，避免重复构建；Windows 继续直接监控源码。
- 监控启动等待上限从 30 秒提高至 120 秒，等待期间响应 `stop` 取消。补充跨平台回归测试，并验证真实 WSL 同步、热构建和失败恢复。
- 修正 Microsoft Store 更新候选验证，避免错误报告可用更新；修正示例中的准备预览命令为只读 `check --json`。

WSL 的 `watch` 路径须在源码同步范围内，详见[源码监控配置](../project-config.md)。升级前停止使用目标控制程序的项目，升级后按需启动。项目声明、注册和 CLI JSON 的格式版本保持不变。

Windows 更新：

```powershell
scoop update
scoop update dev-tools
```

从 Windows 更新 WSL 同版本部署：

```powershell
dev-tools self update -e wsl
```

## English

- Fix WSL projects rolling back healthy services and remaining in recovery after monitor initialization timed out. Monitoring now reads the synchronized Linux workspace; source synchronization receives edits from the original directory. Project declarations and Git state still come from the original source.
- Reduce repeated filesystem metadata queries during snapshots while preserving ignored-directory, symlink and regular-file checks. Refresh snapshots after maintenance and builds to avoid duplicate builds. Windows continues to monitor source directly.
- Increase the monitor startup limit from 30 to 120 seconds and honor `stop` cancellation while waiting. Add cross-platform regression coverage and verify real WSL synchronization, hot builds and failure recovery.
- Verify Microsoft Store update candidates before reporting available updates, and use read-only `check --json` in the preparation preview example.

WSL `watch` paths must be included in source synchronization; see [monitoring configuration](../project-config.en.md). Stop projects using the target controller before upgrading, then start them as needed. Project declarations, registrations and CLI JSON format versions are unchanged.
